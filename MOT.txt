When you call model.track, the argument 'bytetrack.yaml' is looked up inside the installed ultralytics package, not in your app’s folder. Which exact directory that is depends on which Python interpreter (and environment) you’re running:
If you run python app.py from your system Python (no conda/venv), it’ll use whatever ultralytics lives in your global site-packages.
If you’ve activated a conda env (e.g. tf_gpu_env) before python app.py, it resolves to that env’s Lib/site-packages/ultralytics/bytetrack.yaml.
Likewise for any virtualenv or venv you’ve activated.

In other words, it’s always in the site-packages directory of the current interpreter:
import ultralytics, os
print(os.path.dirname(ultralytics.__file__))  
# e.g. C:\Users\you\anaconda3\envs\tf_gpu_env\Lib\site-packages\ultralytics
Under that folder you’ll find bytetrack.yaml. It does not live next to your app.py unless you explicitly copy it there or give track­er= an absolute or relative path to a file in your project.
